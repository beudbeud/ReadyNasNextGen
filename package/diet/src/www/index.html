These settings change how the data volume is written. A mistake or a crash can leave the disks different and lose recent files: only with a backup of /c, after reading docs/XRAID.md.

Technical details
RAID:

      

      
Disks

        

        
A SMART report wakes the disk.

        
A self-test runs inside the disk, in the background: the data are not touched and the disk stays usable (a little slower). Its result shows here when it ends.

        

        

          
          

        

      

    

  


  
  

    

      

        
Network shares (SMB)

        
SMB service

        

        

          
          
        

        
A share is the folder /c/name; a new share is writable and needs no password. “Remove” takes the share off the network without deleting the folder or its contents.

        
        
Off by default: this NAS encrypts without hardware help, which slows transfers a lot. Only useful on a network you do not trust; when on, a client that asks for encryption gets it. SMB restarts when this is changed.

        
        
        
Signing guards against tampering on the network, but this NAS computes it without hardware help: signed transfers are about 3 times slower. The client decides: Windows 11 24H2 and macOS ask for signing and get it, so they keep working; Linux (file manager, mount.cifs) does not by default and stays fast. Signing cannot be refused to a client that asks for it; “Required” makes every client sign. SMB restarts when this is changed.

      

      

        
NFS exports

        

        

        

        

          
          
          
          
        

        
The folder must exist (an SMB share creates it). Changes apply at once (exportfs -ra).

      

    

  


  
  

    

      

        
Share users

        

        

          
          
          
        

        
These accounts open the shares that are not “no password”. Entering an existing name changes its password. Deleting an account leaves its files untouched.

        
The same password opens WebDAV and rsync (personal folder /c/home/name and shares). An account created earlier must set its password again.

      

    

  


  
  

    

      

        
Services

        

        
A service stopped here stays stopped after the NAS restarts.

      

      

        
Prometheus metrics

        

        
        
Off by default. Recommended: keep the authentication and give Prometheus a read-only token (authorization: credentials: <token>). Values are refreshed every 15 s while this interface is open, otherwise every 60 s. Changing this setting restarts the web server.

      

      

        
API access tokens

        

        

          
          
          
        

        

        
For scripts and Prometheus: the header “Authorization: Bearer <token>” on https://<NAS>/api/v1/<action> (docs/API.md). A token is shown only once: only a salted hash of it is kept. A read-only token cannot change anything; actions also need the header “X-Diet: 1”.

Allow writing on the X-RAID


Writing goes through the kernel ext4 driver on the ext3 file system with 16 KB blocks created by RAIDiator, every write going to both disks. This path has not been tested for long yet: a backup of /c is strongly recommended. The volume is unmounted and mounted again; SMB, NFS, DLNA, rsync and WebDAV are stopped meanwhile. The safeguards of nas-raid may keep it read-only.













Accept the quick check


The quick check found no difference, but the superblock records an unclean shutdown (crash or power cut). Only the journals, the file system and LVM metadata and random samples were compared: file data written at the time of the crash may still differ between the disks, and would then read differently depending on the disk. Accepting does what a successful full check does: the superblock is put back clean and, if writing is on, /c is remounted read-write at once. A full check (several hours) or a repair remain the safe options.
